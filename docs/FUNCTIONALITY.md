# Функционал и логика работы бота tezJumush

## Общее описание

Telegram-бот — биржа труда. Две роли: **работодатель** (публикует вакансии) и **соискатель** (откликается на вакансии). Один пользователь может быть обоими одновременно.

---

## Архитектура

```
bot.py                        — точка входа, регистрация роутеров, планировщик
config.py                     — переменные окружения
handlers/
  start.py                    — /start, главное меню, deep link отклик
  profile.py                  — анкета соискателя (создание, редактирование)
  employer.py                 — вакансии (создание, редактирование, удаление)
  applications.py             — отклики, выбор/отклонение кандидатов
  reminders.py                — подтверждение/отказ от работы, оценка
  admin.py                    — команды администратора
database/
  models.py                   — User, Job, JobResponse, Rating, Resume, ActionLog
  db_connection.py            — подключение к БД, SessionLocal
services/
  notification_service.py     — планировщик напоминаний (4ч / 45мин)
  rating_service.py           — расчёт рейтинга
vacancy_fsm.py                — FSM состояния для создания/редактирования вакансии
resume_fsm.py                 — FSM состояния для создания/редактирования анкеты
```

---

## Модели данных

### User
Единая модель для соискателя и работодателя.
- `telegram_id`, `username`, `phone`
- Анкета: `name`, `age`, `gender`, `experience`, `about`, `last_work_date`
- Рейтинг: `average_rating` (начальный 5.0), `completed_jobs`, `refusals_count`
- Чёрный список: `is_blacklisted`, `blacklist_until`

### Job (вакансия)
- `job_type`: `LONG_TERM` (долгосрочная) / `ONE_TIME` (разовая)
- `all_info` (JSON): `title`, `address`, `requirements`, `payment`, `schedule`
- `people_needed`, `people_confirmed`
- `work_start_time`, `work_end_time`
- `status`: см. жизненный цикл ниже

### JobResponse (отклик)
- `job_id`, `user_id`
- `status`: `PENDING → ACCEPTED / REJECTED → CONFIRMED / REFUSED`
- `is_selected` — основной кандидат
- `is_reserve` — резервный кандидат

### Rating
- `job_id`, `worker_id`, `employer_id`, `rating` (1–5)

---

## Жизненный цикл вакансии

```
OPEN
  └─ получен отклик, набрано < people_needed → IN_PROGRESS
       └─ набрано = people_needed → CANDIDATES_SELECTED
            └─ работники подтвердили выход → CONFIRMED
                 └─ работа завершена → COMPLETED
  └─ отменена → CANCELLED
```

## Функционал по модулям

### /start и главное меню (`handlers/start.py`)

- `/start` — приветствие, регистрация пользователя в БД
- Deep link `/start job_{id}` — при нажатии кнопки "Откликнуться" в канале открывает бота и сразу запускает логику отклика на вакансию
- Главное меню (ReplyKeyboard):
  - 📝 Моё резюме
  - ✉️ Выложить вакансию
  - 📋 Мои вакансии
  - 📞 Связаться с админом

---

### Анкета соискателя (`handlers/profile.py`)

**Создание анкеты** (FSM: `ResumeForm`):
1. Имя (ФИО)
2. Возраст (14–100)
3. Пол (кнопки: Мужской / Женский)
4. Опыт работы
5. О себе
6. Телефон (формат: `0XXXXXXXXX`)

Данные сохраняются в `User` (обновляются при повторном заполнении).

**Редактирование анкеты** (FSM: `EditResumeForm`):
- Через кнопку "✏️ Редактировать анкету" или callback `edit_resume_{id}`
- Можно редактировать отдельные поля: имя, возраст, пол, опыт, о себе

**Просмотр**:
- `/my_profile` — показывает анкету + рейтинг + статус блокировки
- `/my_rating` — статистика: рейтинг, выполнено работ, отказов, последний выход

---

### Вакансии (`handlers/employer.py`)

**Создание вакансии** (FSM: `VacancyForm`):
0. Тип: Долгосрочная / Разовая
1. Описание работы
2. Адрес
3. Требования (пол, опыт)
4. Оплата (только цифры)
5. График / время
6. Количество человек (1–10)

После заполнения вакансия публикуется в Telegram-канал в нужный топик:
- Долгосрочные → `REGULAR_THREAD_ID`
- Разовые → `PART_JOB_THREAD_ID`

К сообщению прикрепляется кнопка **"📝 Откликнуться"** — url-кнопка с deep link `t.me/{BOT_USERNAME}?start=job_{id}`.

**Редактирование вакансии** (FSM: `EditVacancyForm`):
- Через "📋 Мои вакансии" → кнопка "✏️ Редактировать"
- Можно редактировать: адрес, описание, оплату, требования, график
- После редактирования сообщение в канале обновляется автоматически

**Удаление вакансии**:
- Через "📋 Мои вакансии" → кнопка "🗑 Удалить"
- Удаляет из БД и из канала

**Антиспам**: не-админы могут публиковать вакансию не чаще 1 раза в 5 минут.

---

### Отклики (`handlers/applications.py`)

**Отклик на вакансию**:
- Пользователь нажимает кнопку в канале → открывается бот через deep link
- Если анкета заполнена → отклик сразу отправляется работодателю и всем админам
- Если анкеты нет → запускается FSM заполнения анкеты, после чего отклик отправляется автоматически
- Повторный отклик на ту же вакансию заблокирован
- Заблокированные пользователи не могут откликаться

**Карточка отклика** (отправляется работодателю и админам):
- Данные вакансии: название, адрес, оплата, график
- Данные кандидата: имя, возраст, пол, опыт, о себе, телефон, рейтинг, дата последнего выхода

**Кнопки на карточке отклика**:
1. ✅ Выбрать как основного → FSM `SelectCandidateForm`:
   - Запрашивает дату выхода на работу
   - Запрашивает уточняющее сообщение
   - Обновляет статус отклика → `ACCEPTED`, `is_selected=True`
   - Обновляет `job.people_confirmed`, статус вакансии
   - Отправляет кандидату уведомление с датой и сообщением
2. 📋 Выбрать как резервного → `is_reserve=True`, уведомляет кандидата
3. ❌ Отклонить → FSM `RejectCandidateForm`:
   - Запрашивает текст отказа
   - Обновляет статус → `REJECTED`
   - Отправляет кандидату сообщение об отказе

### Напоминания и подтверждения (`handlers/reminders.py`)

**Планировщик** (запускается каждые 5 минут в `bot.py`):
- За 4 часа до начала работы → уведомление с кнопками "Приду / Не смогу"
- За 45 минут до начала → финальное подтверждение
- После окончания работы → запрос оценки работника у работодателя

**Отказ от работы** (за 4ч или 45мин):
- `refusals_count += 1`
- При 3+ отказах → автоматическая блокировка на 30 дней
- `job.people_confirmed -= 1`, статус вакансии откатывается
- Работодатель и админы получают уведомление
- Если есть резервный кандидат → ему автоматически отправляется предложение, он становится основным

**Оценка работника** (`rate_worker_{job_id}_{worker_id}_{rating}`):
- Работодатель ставит оценку 1–5 после завершения работы
- Пересчитывается `average_rating` с учётом штрафа за отказы (-0.3 за каждый)
- `completed_jobs += 1`
- Работник получает уведомление с новым рейтингом

---

### Рейтинговая система (`services/rating_service.py`)

- Начальный рейтинг: **5.0**
- Формула: `avg(оценки) - (refusals_count × 0.3)`, минимум **1.0**
- Штраф применяется при каждом пересчёте
- Отображается везде: в карточке отклика, профиле, уведомлениях

---

### Система уведомлений (`services/notification_service.py`)

| Событие | Кому | Когда |
|---|---|---|
| Новый отклик | Работодатель + все админы | Сразу |
| Выбран как основной | Кандидат | Сразу |
| Выбран как резервный | Кандидат | Сразу |
| Отклонён | Кандидат | Сразу |
| Напоминание о работе | Работник | За 4ч и 45мин |
| Отказ работника | Работодатель + админы | При отказе |
| Предложение резервному | Резервный кандидат | При отказе основного |
| Запрос оценки | Работодатель | После окончания работы |
| Оценка получена | Работник | После оценки |
| Блокировка | Работник | При 3-м отказе |
| Вакансия не подтверждена | Работодатель | За 2ч до начала |

### Администрирование (`handlers/admin.py`)

Доступно только пользователям из списка `ADMINS` в `.env`.

| Команда | Описание |
|---|---|
| `/stats` | Общая статистика: пользователи, вакансии, отклики, оценки |
| `/user_info {id}` | Полная информация о пользователе |
| `/blacklist` | Список заблокированных пользователей |
| `/unblock {id}` | Разблокировать пользователя |
| `/logs {job_id}` | История действий по вакансии |

Админы также получают копию каждого отклика с кнопками выбора/отклонения.

## Конфигурация (`.env`)

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота |
| `BOT_USERNAME` | Username бота (для deep link кнопки) |
| `ADMINS` | ID администраторов через запятую |
| `CHANNEL_ID` | ID канала для публикации вакансий |
| `CHANNEL_URL` | URL канала |
| `DATABASE_URL` | Строка подключения к MySQL |
| `REGULAR_THREAD_ID` | Топик для долгосрочных вакансий |
| `PART_JOB_THREAD_ID` | Топик для разовых работ |
| `RESUME_THREAD_ID` | Топик для анкет |
